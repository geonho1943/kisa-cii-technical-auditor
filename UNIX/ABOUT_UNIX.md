# CIIP Audit Linux 0.2.0

2026 주통기 상세가이드 Unix **U-01~U-67** Bash 점검기. 배포판 이름을 기준으로 주 OS/예외 OS를 나누지 않고 사용 가능한 명령·서비스 관리 방식·설정·Runtime 증거를 확인합니다.

전체 Linux 호환성을 목표로 하지만 모든 OS/Version의 실기 검증을 완료하지 않았습니다. **환경·서비스 Provider·설정 경로에 따라 수정 또는 추가 검증이 필요할 수 있습니다.**

## 실행

**`ciip_linux_2026.sh` 하나만 복사**하면 실행할 수 있습니다. Bash 4.4 이상과 Linux 기본 명령이 필요합니다. 대량 파일 탐색·권한 점검에는 GNU find의 `-printf`가 필요하므로 BusyBox 도구만으로 모든 항목의 실행을 보장하지 않습니다. Target에는 Python·jq가 필요하지 않습니다.

```bash
# 설명·설정 확인. 점검과 결과 파일 생성 없음
bash ciip_linux_2026.sh --help
bash ciip_linux_2026.sh --show-config

# Script 상단의 사용자 설정을 검토한 후 실행
sudo bash ciip_linux_2026.sh

# 비민감 설정을 인자로 지정
sudo bash ciip_linux_2026.sh --set output_dir=./results --set check_ids=U-01,U-18,U-63

# 부하 우선순위와 전체 실행 시간을 외부에서 제한하는 선택 예시
sudo nice -n 19 ionice -c3 timeout 3600 bash ciip_linux_2026.sh
```

설정과 간단한 설명은 상단 `AUDIT_CONFIG`와 주석에 모여 있습니다. Type·예시는 [설정 변수 설명](VARIABLES.md)을 참조합니다. 정책 공란을 임의로 안전한 값으로 채우지 않습니다. 비밀번호/Hash/Token을 입력하는 설정은 없습니다. `--validate-config`는 실행 설정을 검증하며, 조직 정책의 완전성·승인 여부까지 검증하지 않습니다.

## 결과

`./audit-results/audit.<임의값>/`에 아래 파일을 생성합니다.

- `report.txt`: 항목별 조회 출처·검사값·판정·이유·추가 확인 내용. 정상 파일의 소유자·권한도 조회 기록에 남깁니다.
- `result.json`: 환경·범위·선택/미선택 항목과 결과 배열. 항목의 목적·위험·가이드 페이지를 포함합니다.
- `items.jsonl`: 항목별 결과 Record.

결과 폴더 700, 파일 600. 계정명·경로·권한·일반 설정값은 보존하고, Hash·인증 문자열은 Masking합니다. 결과 파일에는 보안 상태가 포함되므로 접근 권한을 유지하십시오.

`PASS_MAX_DAYS:99999`, `uid:0 gid:0 mode:644`처럼 검사한 값을 기록합니다. JSON의 항목별 근거 요약은 최대 24,000자로 제한되므로 상세 조회값은 `report.txt`를 함께 확인하십시오. 이 요약 길이 제한은 파일 탐색 건수 제한과 별개입니다.

| 상태 | 의미 |
| --- | --- |
| GOOD | 수집 증거가 구현된 가이드 조건 충족 |
| VULNERABLE | 가이드 취약 조건 또는 입력한 승인 정책 미충족 증거 |
| MANUAL | 정책·업무 필요성·복잡한 유효 설정·Provider 추가 확인 필요 |
| ERROR | 권한·명령·Parsing·Timeout·파일 탐색 조회 실패 등 기술적 실패 |
| NOT_APPLICABLE | 적용 대상이 아님을 입증한 경우에만 사용할 상태 |

서비스 조회 실패 시 Process·Socket·설치 정보로 보완합니다. `systemctl` 없음이나 조회 실패를 서비스 미사용으로 바꾸지 않습니다. 미사용이 확인돼도 가이드 항목별 조건에 따라 판정합니다.

**67개 항목 모두에 검사 함수가 있지만, 모든 항목이 자동 확정되는 것은 아닙니다.** 복잡한 PAM/SSH Include, Firewall 순서·외부 ACL, NFS Client 적절성, Mail/DNS Vendor Patch·Backport, 로그 정책 등은 증거와 수동 확인 지시를 제공합니다.

- U-01은 `sshd -T`와 SSH 설정을 확인합니다. 해석 가능한 Include만으로 수동 판정하지 않으며, Match 조건이나 미해석 설정은 추가 확인합니다.
- U-02는 실제 비밀번호 사용기간이 기준을 벗어나면 다른 PAM 정책의 불확실성과 별개로 `VULNERABLE`을 반환합니다. 승인 예외는 운영자가 검토합니다.
- 외부 NSS 계정이 설정된 경우 로컬 계정의 양호 결과만으로 전체 계정을 양호로 단정하지 않습니다. `sss`는 SSSD 활성 또는 설정 파일 존재, `compat`는 passwd의 `+` 항목 존재를 함께 확인합니다.
- U-37은 cron/at 명령의 SUID/SGID 자체를 취약으로 처리하지 않고 소유자·쓰기 권한을 검사합니다. cron spool은 root 또는 파일명에 해당하는 계정 소유를 허용합니다.
- U-67은 로그의 타인 쓰기 권한과 소유자를 검사합니다. root 외 허용 계정은 `approved_log_accounts`로 지정하며, UID 1~999라는 이유만으로 자동 승인하지 않습니다.

| Exit code | 의미 |
| --- | --- |
| 0 | 실행 완료, ERROR 없음. 취약·수동 항목이 없다는 뜻은 아님 |
| 2 | 사전 검증·출력·실행 실패 |
| 3 | 결과를 저장했으나 ERROR 항목 존재 |
| 130 | 처리 가능한 중단 후 부분 결과 저장 |

## 수명·운영 영향

별도 Bash Process로 실행하며 `source` 실행은 설정 변수를 만들기 전에 거부합니다. 사용자/시스템의 영구 환경변수·Profile·서비스 설정을 수정하지 않습니다. 임시 자원은 종료 시 정리합니다. 강제 종료·전원 차단에서 정리 코드 실행까지 보장하지 않으며 Swap/Dump 제어·메모리 덮어쓰기는 하지 않습니다.

계정·서비스·Firewall·권한을 변경하거나 패치를 설치하는 명령은 호출하지 않습니다. 조회·파일 탐색 부하는 발생합니다. 선택 항목·탐색 범위와 일부 명령의 Timeout을 상단에서 조정할 수 있습니다. Script 내부에 전체 실행 시간이나 파일 탐색 시간·건수 한도는 없습니다. 전체 실행 제한이 필요하면 위의 외부 `timeout` 예시를 사용하십시오.

U-15·U-23·U-25·U-33은 선택된 항목의 조건에 맞는 파일만 수집하며, 탐색 루트마다 항목별로 find를 한 번 실행합니다. `-xdev`를 유지하고 `/proc`, `/sys`, `/dev`, 결과 저장 경로와 하위 Mount를 제외합니다. U-26의 `/dev` 직접 점검은 별도입니다. 탐색이 끝난 뒤 수집값을 판정하고 실제 조회 실패는 근거와 함께 기록합니다. U-15의 소유자·그룹 없음은 find로 구분하며, 외부 NSS 조회 범위가 불확실하면 추가 확인합니다. 선택 항목에 필요한 서비스·계정 정보만 조회합니다.
